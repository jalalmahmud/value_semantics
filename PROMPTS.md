# Generation Prompts & Decoding Settings

This file documents the prompts and model settings used to generate the SQL for each condition, to the
extent they can be released from this package. The generated SQL itself (all conditions, per case) is in
the label sheets under `nl2sql_results/`.

**Verifying these strings.** The strings marked **[exact]** below are copied verbatim from the
experiment code at the cited source locations. The runners and the `value_semantics/` implementation are
**shipped in this package**, so you can verify these strings directly in the code — and execute them
(see README §3). Strings marked **[illustrative]** are schematic templates with placeholder names
(`<table>.<column>`, `{question}`), not literal transcripts.

## Model & decoding (all conditions)

- **Model:** GPT-4o, via the OpenAI Chat Completions API.
- **Decoding:** `temperature = 0`; no `max_tokens`/`top_p`/`seed` override (API defaults). **[exact]**,
  from `OpenAIProvider.complete` (`value_semantics/nl2sql/providers/openai_provider.py`), which sets
  `temperature = 0` for GPT-4o. Note: `temperature = 0` reduces but does not guarantee identical outputs
  across API runs.
- **Runs:** a single generation per case per condition.
- **System prompt:** identical across all four conditions (below).

### Shared system prompt — [exact]

From `SYSTEM_PROMPT` in `value_semantics/nl2sql/prompt_builder.py` (the source uses backslash
line-continuations, so the break shown in the first sentence is a source-width wrap, not part of the
string):

````
You are an expert SQL assistant. Your job is to convert natural language questions into correct,
executable SQL queries.

Rules:
- Output only a single SQL query inside a ```sql code block.
- Do not explain your reasoning outside the code block.
- Use standard SQL that is compatible with PostgreSQL unless told otherwise.
- If the question is ambiguous, make the most reasonable interpretation.
- Use table and column names exactly as provided in the schema.
- Never hallucinate columns or tables that are not in the schema.
````

## Per-condition user prompts

**PM — prompt-mediated VSTs — [exact]**, from `generate_prompt_mediated` in
`benchmarks/run_vsl_benchmark_comparison.py` (the f-string is reproduced literally; `{...}` are its
runtime substitutions):

````
Database schema:
```sql
{schema_text}
```

{vst_hints}

Question: {question}

Write a SQL query that answers the question using the semantic guidance above.
Return only a ```sql code block.
````

`{vst_hints}` is produced by `build_vst_hint_text`; its rendering is **[illustrative]** (placeholder
names; one line per column, only the fields that apply):

```
VALUE SEMANTIC METADATA (use to guide SQL generation):
  <table>.<column> | role=<role> | process=<process_role> | IDENTIFIER: do not aggregate or compare
  magnitudes | should_not_sum=True | requires_temporal_context=True | outlier_p90=<value> |
  derived_metric=<formula_template>
```

**D2 — matched prose — [exact]**, from `generate_vst_prose` in
`benchmarks/run_data_dictionary_baseline.py`:

````
Database schema:
```sql
{schema_text}
```

{vst_prose_text}

Question: {question}

Write a SQL query that answers the question using the schema and column notes above.
Return only a ```sql code block.
````

`{vst_prose_text}` is produced by `build_vst_prose_text` — the **same VST facts as PM**, rendered as
neutral declarative prose with no imperatives or flags. Rendering is **[illustrative]**:

```
COLUMN NOTES (descriptive):
  <table>.<column> serves the role of <role>; participates as <process_role> within a process; holds
  values that are not meaningfully additive; is interpretable only within a temporal context.
```

PM and D2 carry the *same underlying VST facts* in different surface forms — this is the
information-matched comparison in the paper.

**D1 — data-dictionary (description-only baseline).** The accompanying context is a set of plain column
*descriptions* generated by GPT-4o from the schema, then reviewed/corrected by the authors. The frozen
**description-generation** prompt is shipped verbatim as `generate_data_dictionary.py` (inspect it
there). The D1 **SQL-generation** prompt — **[exact]**, from `run_data_dictionary_baseline.py`:

````
Database schema:
```sql
{schema_text}
```

{dictionary_hints}

Question: {question}

Write a SQL query that answers the question using the schema and column descriptions above.
Return only a ```sql code block.
````

`{dictionary_hints}` is produced by `build_dictionary_hint_text` from the GPT-4o-generated,
author-reviewed column descriptions.

**PE — planner-enforced VSTs.** PE does not use a flat prompt block: the VSL planner consumes the same
VSTs, emits an executable plan, and validates/repairs the generated SQL against the VSTs' admissible
operations. The planner and validator logic are **shipped** in `value_semantics/vst/planner.py`,
`value_semantics/vst/validator.py`, and `value_semantics/planning/` — inspect them there. The
PE-generated SQL and its verdicts are in `vsl_human_evaluations_filled_v2.md`, and PE can be rerun via
README §3(b).
